# 阶段 01：前置基础

## 阶段目标

这一阶段的目标不是马上写播放器，而是建立后续所有章节都会使用的共同语言：

- 能独立编译、运行一个最小 C++ 程序。
- 知道 Windows 下编译、链接和运行时 DLL 的区别。
- 能解释音频采样、视频帧、容器、编码、数据包、帧和时间戳。
- 能用 FFmpeg 命令行生成测试媒体，并用 `ffprobe` 检查媒体信息。
- 能读懂一个调用 `libavformat` 的小程序，并正确关闭资源。

## 学习顺序

建议严格按下面的依赖顺序学习。每个主题都完成“阅读 -> 实验 -> 复述 -> 检查”，再进入下一项。

| 顺序 | 主题 | 先掌握什么 | 完成标志 |
|---|---|---|---|
| 1 | [[01-前置基础/C++基础]] | 变量、函数、指针、类、RAII、错误处理 | 能写并编译一个读取命令行参数的 C++ 程序 |
| 2 | [[01-前置基础/计算机与音视频基础]] | 计算机模型、采样、像素、容器、时间基、FFmpeg 对象 | 能运行 `media_info.cpp`、`timestamp_demo.cpp` 和 PCM 实验 |
| 3 | [[01-前置基础/CMake与工程]] | 目标、依赖、Debug/Release、构建目录 | 能用 CMake 重建前两个实验 |
| 4 | [[01-前置基础/Git与调试]] | 提交、断点、调用栈、日志和复盘 | 能记录一次错误并用调试器定位原因 |

### 为什么 C++ 基础排在音视频基础前面

音视频概念可以先用命令行理解，但 C++ + FFmpeg 示例会同时出现指针、结构体、错误码、库链接和资源释放。先把最少的 C++ 语法补好，后面就能把注意力放在媒体数据本身。

### 为什么音视频基础排在 CMake 前面

先知道“要链接哪些库、为什么需要 DLL”，再学习 CMake 的目标和依赖，配置文件就不再是需要死记的模板。若你已经熟悉 CMake，也可以把主题 2 和主题 3 交替学习。

## 阶段实践

### 实践 1：最小程序和命令行参数

使用 [[01-前置基础/C++基础]] 中的示例，完成：

- `hello.exe` 输出一行文本。
- `args.exe sample.mp4` 输出收到的文件路径。
- 输入不存在的路径时输出明确错误，并返回非零退出码。

### 实践 2：媒体基础实验

完成 [[01-前置基础/计算机与音视频基础]] 中的实验：

1. 用 FFmpeg 生成 `sample.mp4`。
2. 用 `ffprobe` 记录容器、视频流和音频流的属性。
3. 编译并运行 `media_info.cpp`。
4. 编译并运行 `timestamp_demo.cpp`。
5. 用 C++ 生成裸 PCM，并转换为 WAV。

### 实践 3：整理成 CMake 工程

把 `media_info.cpp`、`timestamp_demo.cpp` 和 `generate_pcm.cpp` 放进一个工程，要求：

- `cmake -S . -B build` 能生成构建目录。
- `cmake --build build --config Debug` 能构建 Debug 版本。
- 不把 `build` 目录提交到 Git。
- README 中记录 FFmpeg 根目录和运行时 DLL 的位置。

### 实践 4：故意制造并记录错误

依次制造以下错误，并把“错误阶段、原因、修复动作”写到 [[12-问题记录与复盘/问题记录模板]]：

- 删除或改错头文件路径。
- 删除或改错 `.lib` 路径。
- 不设置 DLL 所在目录就启动程序。
- 给裸 PCM 传入错误的采样率或声道数。
- 传入不存在的媒体路径。

## 阶段检查

### 知识检查

- [ ] 我能解释程序、进程、线程、文件、内存和 DLL 的区别。
- [ ] 我能说出编译、链接、运行三个阶段分别查什么。
- [ ] 我能计算 PCM 码率，并解释位深和采样率的影响。
- [ ] 我能区分容器、编码、流、包和帧。
- [ ] 我能用自己的话解释 PTS、DTS 和 time base。
- [ ] 我能解释 `AVFormatContext`、`AVStream`、`AVCodecParameters` 的职责。

### 操作检查

- [ ] `ffmpeg -version` 和 `ffprobe -version` 能运行。
- [ ] 我能从命令行生成一个 5 秒的音视频文件。
- [ ] 我能用 `ffprobe -show_streams -show_format` 查看它。
- [ ] 我能在 x64 Developer PowerShell 中构建 FFmpeg C++ 示例。
- [ ] 我能区分缺头文件、缺 `.lib` 和缺 DLL 三种错误。
- [ ] 我能在程序退出前正确释放已打开的 FFmpeg 资源。

### 阶段出口

满足以下条件后，进入 [[02-Windows开发环境/阶段02-Windows开发环境]]：

1. 不看教程也能完成一次从生成测试媒体到读取媒体信息的流程。
2. 能画出“文件 -> 解封装 -> AVPacket -> 解码 -> AVFrame”的数据流。
3. 能解释同一个时间戳在 `1/1000` 和 `1/90000` 两个 time base 下为何代表不同时间。
4. 能在问题记录中完整写出至少一次构建错误的排查过程。

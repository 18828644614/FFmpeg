# 媒体文件与容器

> 本章的目标是让你看懂一个媒体文件里面“装了什么”，并能用命令行和 C++ 把它读出来。你不需要先会写播放器，也不需要先理解 H.264 或 AAC 的压缩数学。

## 你学完本章应该能做什么

- 用自己的话解释文件、容器、流、编码、数据包和帧的区别。
- 看懂一个 MP4、MKV、MPEG-TS 或 WAV 文件大致由哪些部分组成。
- 区分封装、解封装、重封装和转码，不再把“改扩展名”误认为格式转换。
- 用 `ffprobe` 查看容器级信息、流级信息、元数据和时间信息。
- 判断一个任务是“只换盒子”还是“必须重新编码”。
- 在 Windows + CMake + MSVC 环境下编译一个 C++ 媒体信息查看器。
- 用 C++ 完成一次不解码、不重新编码的重封装，并理解时间戳为什么要换算。
- 遇到“无法打开文件、缺少 DLL、容器不支持编码、输出没有声音”等问题时，知道先查哪一层。

## 三、先从“文件”和“盒子”开始

### 3.1 媒体文件本质上是字节

计算机中的文件本质上是一串字节，也就是数值为 0 到 255 的数据。图片、文字、压缩包和视频都只是“解释这些字节的规则”不同。

```text
sample.mp4
    |
    +-- 一串字节
    +-- MP4 规则说明哪些字节是标题、轨道、时间和媒体数据
    +-- H.264/AAC 规则说明媒体数据如何被解码
```

文件扩展名只是给人和操作系统看的提示。把 `sample.mp4` 改名成 `sample.mkv` 不会改变里面的任何字节，因此它仍然是 MP4 数据。真正的格式转换需要程序按照新的规则重新写文件。

### 3.2 容器是什么

**容器（container）**可以先理解成“装媒体数据的盒子”。它负责记录：

- 有哪些轨道（也叫流）。
- 每条轨道是什么类型，是视频、音频、字幕还是其他数据。
- 每条轨道使用什么编码。
- 数据的时间顺序和时间戳。
- 标题、作者、语言、封面、章节等附加信息。
- 有时还会保存索引，帮助播放器快速跳到某个位置。

容器通常不负责把画面压缩得更小。压缩规则由编码器决定，容器负责把压缩结果和播放所需的说明组织起来。

可以用“搬家箱子”来记忆：

```text
容器 = 箱子
流 = 箱子里的不同轨道
编码 = 轨道上数据的压缩规则
数据包 = 一小包压缩数据
帧 = 解码后可显示或播放的数据单位
```

### 3.3 容器、流、编码的关系

假设一个文件包含画面和声音：

```text
movie.mp4                         容器：MP4
  |
  +-- Stream 0: video             视频流
  |     Codec: H.264              编码：H.264
  |     Packets -> decoded frames 数据包 -> 视频帧
  |
  +-- Stream 1: audio             音频流
        Codec: AAC                编码：AAC
        Packets -> decoded frames 数据包 -> 音频帧
```

这里有两个非常重要的结论：

1. `.mp4` 只说明外层容器，不等于“里面一定是 H.264 + AAC”。
2. H.264 是编码格式，不是容器。H.264 可以放进 MP4、MKV、MPEG-TS 等多个容器。

### 3.4 一张术语对照表

| 术语 | 通俗解释 | 示例 |
|---|---|---|
| 文件 file | 磁盘上的字节集合 | `sample.mp4` |
| 容器 container | 组织轨道、时间和元数据的外层格式 | MP4、MKV、MPEG-TS |
| 流 stream | 容器中的一条连续轨道 | 视频流、音频流、字幕流 |
| 编码 codec | 压缩和还原媒体数据的规则 | H.264、HEVC、AAC、Opus |
| 数据包 packet | 文件中读出的压缩数据块 | 一个 H.264 压缩包 |
| 帧 frame | 解码后可以处理的数据单位 | 一张图、1024 个音频采样 |
| 封装 mux | 把多个流写进一个容器 | H.264 + AAC -> MP4 |
| 解封装 demux | 从容器中取出流和数据包 | MP4 -> 视频包、音频包 |
| 重封装 remux | 不改变编码，只换容器 | MP4 -> MKV，`-c copy` |
| 转码 transcode | 解码后重新编码 | H.265 -> H.264 |

## 四、数据包、帧和关键帧

### 4.1 数据包通常是压缩数据

从文件中读取时，FFmpeg 首先得到的通常是 `AVPacket`。它里面是一段压缩后的字节，并带有：

- `stream_index`：它属于哪条流。
- `pts`：应该在什么播放时间显示或播放。
- `dts`：解码器大致应该在什么顺序处理它。
- `duration`：这段数据覆盖多长时间。
- `flags`：例如是否是关键包。

`AVPacket` 不是“一张图片”。对于视频，解码器可能要接收多个数据包才能输出一帧；对于音频，一个数据包可能包含一小段采样。

### 4.2 帧是解码后的数据

`AVFrame` 一般表示解码后的原始数据：

- 视频帧包含宽度、高度、像素格式和像素平面。
- 音频帧包含采样格式、采样率、声道布局和采样数。

后续程序可以对帧做缩放、裁剪、音量调整、显示或再次编码。

```text
容器文件
  -> 解封装
AVPacket（压缩数据）
  -> 解码
AVFrame（原始数据）
  -> 处理或编码
```

### 4.3 关键帧为什么重要

视频通常不会把每一张画面都完整保存。很多帧只记录“和前后画面相比改变了什么”，因此解码某一帧可能依赖前面的帧。

**关键帧（keyframe）**是可以相对独立解码的起点。播放器拖动进度时，通常先找到目标位置之前最近的关键帧，再从那里开始解码到目标位置。

这会带来三个实际现象：

- 精确剪切经常需要重新编码，或者只能在关键帧处快速剪切。
- 关键帧间隔过大，拖动和启动可能变慢。
- 容器的索引需要帮助程序快速找到关键帧附近的位置。

音频通常比视频更接近“连续的数据包”，但它同样有时间戳和持续时间，不能只按文件字节位置猜播放时间。

### 4.4 交错写入（interleaving）

带声音的视频文件通常不是先写完所有视频再写完所有音频，而是按时间顺序交错保存：

```text
视频包 0 -> 音频包 0 -> 音频包 1 -> 视频包 1 -> 音频包 2 -> ...
```

交错有利于边读边播，尤其是网络或管道输入。`av_interleaved_write_frame` 会根据时间戳帮助输出端交错不同流的数据包。不要自行假设“文件里所有视频包一定连续出现”。

## 五、封装、解封装、重封装和转码

### 5.1 解封装：从盒子里取东西

解封装（demux）是从容器读取流和压缩数据包的过程。FFmpeg 中主要由 `libavformat` 负责：

```text
MP4 文件
   |
   | libavformat
   v
视频 AVPacket + 音频 AVPacket + 字幕 AVPacket
```

解封装本身不一定会解码画面。`ffprobe` 只读取格式和流信息时，通常就停在这一层。

### 5.2 封装：把数据放进盒子

封装（mux）是把压缩数据包、时间戳和元数据按目标容器规则写入文件：

```text
H.264 AVPacket + AAC AVPacket
              |
              | libavformat
              v
            MP4 文件
```

### 5.3 重封装：只换盒子

重封装（remux）把已有的压缩数据包直接复制到另一个容器，不经过“解码 -> 重新编码”：

```text
MP4 解封装 -> H.264/AAC 压缩包 -> MKV 封装
```

命令行通常写成：

```powershell
ffmpeg -i input.mp4 -map 0 -c copy output.mkv
```

`-c copy` 的意思是复制编码数据，不调用编码器。它通常速度快、不会因为再次压缩而损失质量，但目标容器必须支持这些编码和参数。

### 5.4 转码：重新压缩

转码（transcode）至少包含解码和重新编码：

```text
H.265 压缩包
   -> 解码 -> 原始帧 -> H.264 编码 -> H.264 压缩包
```

示例：

```powershell
ffmpeg -i input.mkv -c:v libx264 -c:a aac output.mp4
```

转码通常更慢，也可能损失质量，但可以解决目标容器不支持某种编码、需要改变分辨率、码率或兼容性的问题。

### 5.5 四种操作的判断表

| 操作 | 是否解码 | 是否重新编码 | 典型用途 |
|---|---:|---:|---|
| 查看信息 | 否 | 否 | `ffprobe`、信息查看器 |
| 解封装 | 否 | 否 | 取出包给解码器 |
| 重封装 | 否 | 否 | MP4 换成 MKV |
| 转码 | 是 | 是 | H.265 转 H.264、缩放、改码率 |

## 六、常见容器和文件格式

没有“最好的容器”，只有适合某个目标的容器。选择时要同时考虑播放器支持、编码组合、字幕/附件需求、是否网络传输和是否需要快速拖动。

### 6.1 MP4 / MOV

- MP4 和 MOV 有相近的历史背景，FFmpeg 经常把它们显示为 QuickTime/MOV 家族。
- 浏览器、手机、电视和剪辑软件支持通常很好。
- 常见组合是 H.264/H.265/AV1 视频加 AAC/ALAC 音频，但“常见”不代表“必然”。
- 文件会保存 `moov` 等描述和索引信息。若 `moov` 在文件末尾，网络播放可能需要先下载较多内容。
- `-movflags +faststart` 可以在输出时把必要的索引移动到文件前部，适合点播文件。
- 对字幕、附件和非常规编码的表达能力不如 MKV 灵活。

### 6.2 MKV（Matroska）

- 设计目标是容纳很多类型的流和元数据。
- 适合多音轨、多字幕、章节、封面和附件。
- 对许多编码的兼容性很好，但某些浏览器或硬件设备对 MKV 的支持不如 MP4。
- 也可以装 H.264、H.265、AV1、Opus、AAC 等，容器名不能替你决定编码。

### 6.3 MPEG-TS

- 常见于电视广播、直播和网络传输。
- 数据按传输包组织，适合连续发送和出现丢包的场景。
- 相比 MP4，随机定位、全局时长和元数据能力可能更弱或更依赖额外信息。
- 同一个文件中可能出现时间戳跳变、节目切换和不连续，需要更谨慎地处理。

### 6.4 WebM

- WebM 可以理解为 Matroska 家族中面向网页场景的一组约定。
- 常见视频是 VP8、VP9 或 AV1，常见音频是 Vorbis 或 Opus。
- 适合浏览器和网页媒体，但不是“任何视频都能直接放进去”。例如 H.264 视频不一定符合目标 WebM 播放器的要求。

### 6.5 AVI

- 历史较久，结构简单，很多旧软件仍能读取。
- 对现代编码、时间戳、字幕和流扩展的表达能力有限。
- 看到 AVI 时不要默认它是某一种视频编码；必须用 `ffprobe` 查看流。

### 6.6 WAV、AIFF 和 FLAC

- WAV 常见于 Windows 音频和录音工作流，常见内容是 PCM，也可以包含其他音频编码。
- AIFF 是另一种常见的未压缩或少压缩音频文件格式。
- FLAC 是无损音频编码和文件格式，带有自己的元数据块。日常讨论中常把它当作“音频容器/音频文件格式”，但它不像 MP4 那样通常用来装多条不同类型媒体流。
- 这些格式主要用于音频，不适合拿来装一条视频轨道和多条字幕轨道。

### 6.7 Ogg

- Ogg 是一种开放的容器格式，常见编码包括 Vorbis、Opus 和 Theora。
- 适合开放格式生态和音频场景，但不同设备的兼容性仍要单独验证。

### 6.8 按需求选择容器

| 需求 | 可优先考虑 | 原因 |
|---|---|---|
| 网页、手机、通用交付 | MP4 | 生态和设备支持广 |
| 多字幕、多音轨、章节、附件 | MKV | 容器表达能力灵活 |
| 直播或传输流 | MPEG-TS | 连续发送和传输场景成熟 |
| 浏览器中的 VP9/AV1 + Opus | WebM | 网页约定清晰 |
| 录音和 PCM 编辑 | WAV/AIFF | 工作流简单、兼容性好 |
| 无损音频归档 | FLAC | 压缩后仍可无损还原 |

不要只根据扩展名选择。先确定“目标播放器支持什么编码和容器”，再决定是否重封装或转码。

## 七、元数据、章节、字幕和索引

### 7.1 两层元数据

元数据是“描述媒体的数据”，不是画面和声音本身。常见字段包括标题、作者、语言、封面、创建时间和编码软件。

它至少有两层：

1. **容器级元数据**：描述整个文件，例如标题和整体创建时间。
2. **流级元数据**：描述某一条流，例如音轨语言为 `chi`、视频角度或字幕标题。

因此同一个文件可能同时有：

```text
容器标题：旅行记录
视频流标题：主画面
音频流 0：中文  language=chi
音频流 1：English language=eng
```

### 7.2 字幕、附件和章节

- 字幕可以是文本，也可以是图像字幕；它们可能作为独立流放在容器中。
- MKV 可以放字体附件，播放器用它们渲染字幕。
- 章节是可跳转的时间点和标题，例如“第一章”“采访部分”。
- 封面可能是一张附加图片，也可能被编码成一条特殊的视频流，具体取决于容器和工具。

看到“有字幕”时，要继续问：字幕是独立流、硬编码在画面里，还是外部 `.srt` 文件？只有独立流或外部文件才可以在不重新编码画面的情况下替换。

### 7.3 索引和快速定位

播放器拖动进度时，需要知道“目标时间附近的字节在哪里”。容器可能保存索引，或者依靠包中的时间戳和关键帧逐步寻找。

- MP4 常见的 `moov` 结构保存轨道和索引信息。
- MKV 使用自己的元素和索引结构。
- MPEG-TS 更偏向连续传输，随机定位可能需要扫描或外部索引。
- 索引不等于编码数据。删除或重新生成索引不会自动改变 H.264 或 AAC 的内容。

## 八、时间信息的最小知识

本章只先建立“看得懂”的模型，精确换算见 [[03-FFmpeg基础/时间戳与时间基]]。

### 8.1 PTS、DTS 和 duration

- **PTS（presentation timestamp）**：这一帧或数据包应该在什么时候呈现给用户。
- **DTS（decoding timestamp）**：解码器应该在什么顺序、什么时间处理它。
- **duration**：这个数据包或帧覆盖多长的播放时间。

对于没有复杂帧重排的流，PTS 和 DTS 可能看起来很接近。存在 B 帧等重排时，文件中的解码顺序和显示顺序可能不同，因此不能简单地用“读到第几个包”代替播放时间。

### 8.2 time base 是时间刻度

FFmpeg 通常用 `AVRational` 表示时间基。例如：

```text
time_base = 1/90000
timestamp = 900000
实际秒数 = 900000 * 1/90000 = 10 秒
```

视频流和音频流可以使用不同的时间基，例如视频 `1/90000`、音频 `1/48000`。比较两条流的时间时，要先换算到同一个时间基或统一成秒。

### 8.3 为什么 duration 可能是 unknown

实时输入、损坏文件、没有完整索引的文件或某些网络流可能无法立刻给出可靠总时长。FFmpeg 用 `AV_NOPTS_VALUE` 表示未知时间戳或时长，程序不能把它直接当成 0。

## 九、用命令行观察一个真实文件

下面假设测试文件路径为 `C:\media\sample.mp4`。路径有空格时始终加双引号。

### 9.1 先确认工具可用

```powershell
Get-Command ffmpeg
Get-Command ffprobe
ffmpeg -hide_banner -version
ffprobe -hide_banner -version
```

如果 `Get-Command` 找不到程序，先把 FFmpeg 的 `bin` 目录加入当前 PowerShell：

```powershell
$env:Path = "C:\ffmpeg\bin;$env:Path"
```

这只影响当前窗口。长期配置见 [[02-Windows开发环境/环境变量与DLL]]。

### 9.2 查看容器和流

```powershell
ffprobe -hide_banner "C:\media\sample.mp4"
```

输出中的 `Input #0` 和 `Duration` 主要是容器级信息，下面的 `Stream #0:0`、`Stream #0:1` 是流级信息。重点找：

- `Input #0` 后面的格式名称。
- `Duration` 和整体码率。
- `Stream #0:0` 是 video 还是 audio。
- `Video:` 或 `Audio:` 后面的编码名称、分辨率、采样率和声道。

### 9.3 输出机器可读的 JSON

```powershell
ffprobe -v error `
  -show_entries "format=format_name,format_long_name,duration,size,bit_rate:stream=index,codec_type,codec_name,codec_long_name,width,height,pix_fmt,sample_rate,channels,channel_layout,language" `
  -of json `
  "C:\media\sample.mp4"
```

JSON 只是输出方式，不代表媒体文件是 JSON。容器级字段位于 `format`，每条流位于 `streams` 数组。

### 9.4 观察数据包和关键包

```powershell
ffprobe -v error -select_streams v:0 `
  -show_entries packet=pts_time,dts_time,duration_time,flags,size,stream_index `
  -read_intervals "%+#10" `
  -of csv "C:\media\sample.mp4"
```

`flags` 中常见的 `K` 表示关键包。不同版本、编码器和容器的字段可能略有差异，先看结构，再追求每一列都记住。

### 9.5 不输出文件，只验证输入是否可处理

```powershell
ffmpeg -hide_banner -i "C:\media\sample.mp4" -f null -
```

这个命令会读取输入并把输出丢弃。它适合区分“文件打不开”和“输出参数不合适”。注意最后的 `-` 是标准输出，不是一个名为短横线的文件。

### 9.6 做一次命令行重封装

```powershell
ffmpeg -hide_banner -i "C:\media\sample.mp4" `
  -map 0 -c copy "C:\media\sample.mkv"
```

然后检查结果：

```powershell
ffprobe -hide_banner "C:\media\sample.mkv"
```

如果只想把 MP4 做成更适合点播的布局，可以在输出 MP4 时尝试：

```powershell
ffmpeg -i "C:\media\sample.mp4" -map 0 -c copy -movflags +faststart "C:\media\sample-faststart.mp4"
```

这仍然主要是重封装，不会把 H.264 或 AAC 重新压缩。

### 9.7 什么时候 `-c copy` 会失败

例如把 H.264/AAC 直接复制到 WebM：

```powershell
ffmpeg -i input.mp4 -map 0 -c copy output.webm
```

可能失败，因为目标容器或播放器对这组编码不接受。此时需要选择支持该编码的容器，或者进行转码：

```powershell
ffmpeg -i input.mp4 -c:v libvpx-vp9 -c:a libopus output.webm
```

转码会更慢，并且需要根据质量、码率和编码器支持调整参数。

```cmake
    )
```

- `bin`：运行 `.exe` 时寻找 `.dll`。

### 10.3 `media_inspector.cpp`

```cpp
#include <cstdint>
#include <iomanip>
#include <iostream>
#include <string>

extern "C" {
#include <libavcodec/avcodec.h>
#include <libavformat/avformat.h>
#include <libavutil/avutil.h>
#include <libavutil/channel_layout.h>
#include <libavutil/dict.h>
#include <libavutil/error.h>
#include <libavutil/mathematics.h>
#include <libavutil/pixdesc.h>
}

static std::string ffmpeg_error(int error_code) {
    char buffer[AV_ERROR_MAX_STRING_SIZE] = {};
    av_strerror(error_code, buffer, sizeof(buffer));
    return std::string(buffer);
}

static const char* media_type_name(AVMediaType type) {
    const char* name = av_get_media_type_string(type);
    return name == nullptr ? "unknown" : name;
}

static void print_metadata(const char* owner, const AVDictionary* dictionary) {
    if (dictionary == nullptr) {
        return;
    }

    const AVDictionaryEntry* entry = nullptr;
    while ((entry = av_dict_get(dictionary, "", entry,
                                AV_DICT_IGNORE_SUFFIX)) != nullptr) {
        std::cout << "  " << owner << " metadata: "
                  << entry->key << " = " << entry->value << "\n";
    }
}

static void print_duration(const char* label, std::int64_t value, AVRational time_base) {
    if (value == AV_NOPTS_VALUE || time_base.den == 0) {
        std::cout << label << ": unknown\n";
        return;
    }

    std::cout << label << ": " << std::fixed << std::setprecision(3)
              << value * av_q2d(time_base) << " seconds\n";
}

int main(int argc, char* argv[]) {
    if (argc != 2) {
        std::cerr << "Usage: media_inspector.exe <input-media>\n";
        return 2;
    }

    const std::string input_path = argv[1];
    AVFormatContext* format_context = nullptr;

    int result = avformat_open_input(
        &format_context,
        input_path.c_str(),
        nullptr,
        nullptr
    );
    if (result < 0) {
        std::cerr << "Could not open input: " << input_path << "\n"
                  << ffmpeg_error(result) << "\n";
        return 1;
    }

    result = avformat_find_stream_info(format_context, nullptr);
    if (result < 0) {
        std::cerr << "Could not read stream information: "
                  << ffmpeg_error(result) << "\n";
        avformat_close_input(&format_context);
        return 1;
    }

    std::cout << "FFmpeg version: " << av_version_info() << "\n";
    std::cout << "Input: " << input_path << "\n";

    if (format_context->iformat != nullptr) {
        std::cout << "Container: " << format_context->iformat->name;
        if (format_context->iformat->long_name != nullptr) {
            std::cout << " (" << format_context->iformat->long_name << ")";
        }
        std::cout << "\n";
    }

    print_duration("Format duration", format_context->duration,
                   AVRational{1, AV_TIME_BASE});
    if (format_context->bit_rate > 0) {
        std::cout << "Format bit rate: " << format_context->bit_rate
                  << " bits/s\n";
    } else {
        std::cout << "Format bit rate: unknown\n";
    }
    print_metadata("format", format_context->metadata);
    std::cout << "Stream count: " << format_context->nb_streams << "\n";

    for (unsigned int index = 0; index < format_context->nb_streams; ++index) {
        const AVStream* stream = format_context->streams[index];
        const AVCodecParameters* parameters = stream->codecpar;

        std::cout << "\nStream #" << index << "\n";
        std::cout << "  Type: " << media_type_name(parameters->codec_type) << "\n";
        std::cout << "  Codec: " << avcodec_get_name(parameters->codec_id) << "\n";
        std::cout << "  Time base: " << stream->time_base.num << "/"
                  << stream->time_base.den << " seconds per tick\n";
        print_duration("  Duration", stream->duration, stream->time_base);
        std::cout << "  Start time: ";
        if (stream->start_time == AV_NOPTS_VALUE) {
            std::cout << "unknown\n";
        } else {
            std::cout << stream->start_time * av_q2d(stream->time_base)
                      << " seconds\n";
        }

        if (parameters->codec_type == AVMEDIA_TYPE_VIDEO) {
            const char* pixel_format = av_get_pix_fmt_name(
                static_cast<AVPixelFormat>(parameters->format));
            std::cout << "  Size: " << parameters->width << "x"
                      << parameters->height << "\n";
            std::cout << "  Pixel format: "
                      << (pixel_format == nullptr ? "unknown" : pixel_format)
                      << "\n";
            std::cout << "  Frame rate hint: " << av_q2d(stream->avg_frame_rate)
                      << " fps\n";
        } else if (parameters->codec_type == AVMEDIA_TYPE_AUDIO) {
            std::cout << "  Sample rate: " << parameters->sample_rate << " Hz\n";
            std::cout << "  Channels: " << parameters->ch_layout.nb_channels << "\n";
        }

        if (stream->disposition & AV_DISPOSITION_DEFAULT) {
            std::cout << "  Disposition: default\n";
        }
        if (stream->disposition & AV_DISPOSITION_FORCED) {
            std::cout << "  Disposition: forced\n";
        }
        print_metadata("stream", stream->metadata);
    }

    // This prints FFmpeg's own human-readable format summary to stderr.
    av_dump_format(format_context, 0, input_path.c_str(), 0);
    avformat_close_input(&format_context);
    return 0;
}
```

### 10.4 逐段读懂示例

1. `avformat_open_input` 打开文件，并尝试识别容器。
2. `avformat_find_stream_info` 读取更多数据，补齐流的编码和时长信息。
3. `format_context->iformat` 描述容器；`format_context->streams` 是容器中的流数组。
4. `stream->codecpar` 描述这一条流使用的编码和媒体参数。
5. `stream->time_base` 是这一条流的时间刻度，不能假设音视频相同。
6. `stream->metadata` 和 `format_context->metadata` 是两层不同的元数据。
7. `stream` 和 `codecpar` 是格式上下文内部的借用指针，示例只读取，不调用 `delete`。
8. `format_context` 由 `avformat_open_input` 创建，最后必须用 `avformat_close_input` 释放。

在 `media-container-lab` 目录打开“x64 Native Tools Command Prompt for VS 2022”，或在已经配置好 MSVC 的 PowerShell 中执行：


```powershell

```

```text

Input: C:\media\sample.mp4
Container: mov,mp4,m4a,3gp,3g2,mj2 (QuickTime / MOV)
Format duration: 12.480 seconds
Stream count: 2

Stream #0
  Type: video
  Codec: h264
  Time base: 1/90000 seconds per tick
  Size: 1920x1080

Stream #1
  Type: audio

  Time base: 1/48000 seconds per tick
```

`av_dump_format` 会把另一份摘要写到标准错误输出，所以它可能和前面的 `std::cout` 交错出现，这是正常的。

## 十一、Windows + C++ + FFmpeg 实验二：不重新编码的重封装

这个实验把输入文件中的视频、音频和字幕流复制到新的容器。示例不处理附加数据和附件，以便先集中理解流映射、时间基和包写出。

### 11.1 `media_remux.cpp`

```cpp
#include <iostream>
#include <string>
#include <vector>

extern "C" {
#include <libavcodec/avcodec.h>
#include <libavformat/avformat.h>
#include <libavutil/avutil.h>
#include <libavutil/error.h>
}

static std::string ffmpeg_error(int error_code) {
    char buffer[AV_ERROR_MAX_STRING_SIZE] = {};
    av_strerror(error_code, buffer, sizeof(buffer));
    return std::string(buffer);
}

static bool is_media_stream(AVMediaType type) {
    return type == AVMEDIA_TYPE_VIDEO
        || type == AVMEDIA_TYPE_AUDIO
        || type == AVMEDIA_TYPE_SUBTITLE;
}

int main(int argc, char* argv[]) {
    if (argc != 3) {
        std::cerr << "Usage: media_remux.exe <input-media> <output-media>\n";
        return 2;
    }

    const std::string input_path = argv[1];
    const std::string output_path = argv[2];
    AVFormatContext* input_context = nullptr;
    AVFormatContext* output_context = nullptr;
    AVPacket* packet = nullptr;

    auto cleanup = [&]() {
        av_packet_free(&packet);
        avformat_close_input(&input_context);
        if (output_context != nullptr) {
            if (output_context->pb != nullptr
                && (output_context->oformat->flags & AVFMT_NOFILE) == 0) {
                avio_closep(&output_context->pb);
            }
            avformat_free_context(output_context);
        }
    };

    int result = avformat_open_input(
        &input_context, input_path.c_str(), nullptr, nullptr);
    if (result < 0) {
        std::cerr << "Could not open input: " << ffmpeg_error(result) << "\n";
        cleanup();
        return 1;
    }

    result = avformat_find_stream_info(input_context, nullptr);
    if (result < 0) {
        std::cerr << "Could not read stream information: "
                  << ffmpeg_error(result) << "\n";
        cleanup();
        return 1;
    }

    result = avformat_alloc_output_context2(
        &output_context, nullptr, nullptr, output_path.c_str());
    if (result < 0 || output_context == nullptr) {
        std::cerr << "Could not choose an output container: "
                  << ffmpeg_error(result) << "\n";
        cleanup();
        return 1;
    }

    std::vector<int> stream_map(input_context->nb_streams, -1);
    for (unsigned int input_index = 0;
         input_index < input_context->nb_streams;
         ++input_index) {
        AVStream* input_stream = input_context->streams[input_index];
        if (!is_media_stream(input_stream->codecpar->codec_type)) {
            continue;
        }

        AVStream* output_stream = avformat_new_stream(output_context, nullptr);
        if (output_stream == nullptr) {
            std::cerr << "Could not create output stream\n";
            cleanup();
            return 1;
        }

        result = avcodec_parameters_copy(
            output_stream->codecpar, input_stream->codecpar);
        if (result < 0) {
            std::cerr << "Could not copy codec parameters: "
                      << ffmpeg_error(result) << "\n";
            cleanup();
            return 1;
        }

        // The output muxer chooses the final time base after the header is written.
        output_stream->time_base = input_stream->time_base;
        output_stream->codecpar->codec_tag = 0;
        stream_map[input_index] = static_cast<int>(output_stream->index);
    }

    if ((output_context->oformat->flags & AVFMT_NOFILE) == 0) {
        result = avio_open(&output_context->pb, output_path.c_str(), AVIO_FLAG_WRITE);
        if (result < 0) {
            std::cerr << "Could not open output: " << ffmpeg_error(result) << "\n";
            cleanup();
            return 1;
        }
    }

    result = avformat_write_header(output_context, nullptr);
    if (result < 0) {
        std::cerr << "Could not write output header: "
                  << ffmpeg_error(result) << "\n";
        cleanup();
        return 1;
    }

    packet = av_packet_alloc();
    if (packet == nullptr) {
        std::cerr << "Could not allocate packet\n";
        cleanup();
        return 1;
    }

    while ((result = av_read_frame(input_context, packet)) >= 0) {
        const int output_index = stream_map[packet->stream_index];
        if (output_index < 0) {
            av_packet_unref(packet);
            continue;
        }

        AVStream* input_stream = input_context->streams[packet->stream_index];
        AVStream* output_stream = output_context->streams[output_index];

        packet->stream_index = output_index;
        av_packet_rescale_ts(packet, input_stream->time_base,
                             output_stream->time_base);
        packet->pos = -1;

        result = av_interleaved_write_frame(output_context, packet);
        av_packet_unref(packet);
        if (result < 0) {
            std::cerr << "Could not write packet: " << ffmpeg_error(result)
                      << "\n";
            cleanup();
            return 1;
        }
    }

    if (result != AVERROR_EOF) {
        std::cerr << "Could not read packet: " << ffmpeg_error(result) << "\n";
        cleanup();
        return 1;
    }

    result = av_write_trailer(output_context);
    if (result < 0) {
        std::cerr << "Could not write output trailer: "
                  << ffmpeg_error(result) << "\n";
        cleanup();
        return 1;
    }

    std::cout << "Remuxed: " << input_path << " -> " << output_path << "\n";
    cleanup();
    return 0;
}
```

### 11.2 代码中最容易忽略的地方

- `avformat_alloc_output_context2` 根据输出文件名选择输出容器；因此 `.mkv`、`.mp4` 等扩展名会影响默认选择，但真正能否写出仍取决于容器支持。
- `avcodec_parameters_copy` 复制的是流的编码参数，不是把数据解码后再编码。
- 输入流和输出流的索引可能不同，所以要用 `stream_map` 做映射。
- `av_packet_rescale_ts` 把输入包时间戳从输入时间基换到输出时间基。直接复制整数时间戳会造成播放时间错误。
- `av_interleaved_write_frame` 让多个输出流按时间交错写入。
- `av_write_trailer` 写出文件结尾和可能的索引。没有它，输出文件可能无法正常播放。
- `AVPacket` 是本程序主动申请的对象，使用后要调用 `av_packet_free`；输入流和输出流由格式上下文管理。
- 为了把重点放在流和包上，示例没有复制章节、附件以及全部容器元数据；生产程序应根据目标容器逐项处理这些内容。

```powershell
  "C:\media\sample.mp4" `
```

## 十二、常见错误和排查顺序

遇到问题时，按“输入路径 -> 工具版本 -> 头文件和库 -> 架构 -> DLL -> 容器能力 -> 时间戳 -> 资源释放”的顺序检查。

| 现象 | 常见原因 | 排查方法 |
|---|---|---|
| 改扩展名后播放器打不开 | 只改了名字，没有真正重封装 | 用 `ffprobe` 检查实际容器；使用 `ffmpeg -c copy` 转换 |
| `Invalid data found when processing input` | 文件损坏、路径错误、文件并非媒体或构建不支持 | 先运行 `Test-Path`，再运行 `ffprobe` |
| `Could not open input` | 路径有空格但没有加引号，或当前用户无权限 | 使用完整路径和双引号，检查文件权限 |
| C++ 报 `avformat/avformat.h` 找不到 | `include` 路径未传给编译器 | 检查 `FFMPEG_ROOT/include/libavformat/avformat.h` |
| 链接时报 `cannot open file avformat.lib` | `lib` 路径错误，或下载的是运行时包 | 检查 `FFMPEG_ROOT/lib/avformat.lib` |
| 编译成功，启动提示缺少 `avformat-*.dll` | Windows DLL 搜索路径中没有 FFmpeg `bin` | 当前窗口设置 `$env:Path`，或把 DLL 放到 exe 旁边 |
| `0xc000007b` | x86/x64 混用，或 DLL 与 exe 不匹配 | CMake 使用 `-A x64`，开发包和 DLL 也用 x64 |
| `ffprobe` 能运行，C++ 程序不能运行 | 两者加载了不同版本 DLL | 检查 PATH 顺序、exe 目录和 CMake 的 include/lib 来源 |
| 重封装到 WebM 失败 | H.264/AAC 等编码不符合目标容器约定 | 换用 MKV/MP4，或按 WebM 需要转码为 VP9/AV1 + Opus |
| 输出只有视频没有音频 | `-map` 只选择了视频，或程序过滤掉了音频流 | 使用 `-map 0`，检查 `stream_map` 和输入流类型 |
| 输出播放时长异常或声音变速 | 没有按时间基换算时间戳 | 使用 `av_packet_rescale_ts`，不要直接复制 PTS/DTS 整数 |
| 输出文件存在但打不开 | 没有调用 `av_write_trailer`，或中途异常退出 | 检查所有错误路径，确保正常结束时写 trailer |
| 时长显示 `unknown` | 输入没有可靠总时长或索引 | 把它视为合法结果，按包时间戳处理，不要当作 0 |
| 旧教程要求 `av_register_all` | 教程针对旧版 FFmpeg | 现代 FFmpeg 通常不需要全局注册；以当前头文件和 API 为准 |
| 直接 `delete format_context` 崩溃 | FFmpeg 对象必须用对应释放函数 | 使用 `avformat_close_input`、`av_packet_free` 等 API |
| 输出文件被输入文件覆盖后损坏 | 输入输出路径相同或程序中途失败 | 使用不同输出路径，成功验证后再替换原文件 |

## 十三、练习题

### 练习 1：画出一个 MP4 的内部结构

找一个同时包含视频和音频的 MP4，用下面的格式画图：

```text
文件 -> 容器 -> 流 0 / 流 1 -> 编码 -> 数据包 -> 帧
```

写出每一层的实际名称，例如 `video / h264 / audio / aac`。

**检查点**：你应该能指出 MP4 是容器，H.264/AAC 是编码，不能把它们写成同一个概念。

### 练习 2：扩展名实验

复制一个测试文件，把副本改名为 `.mkv`，然后分别运行：

```powershell
ffprobe "renamed.mkv"
ffmpeg -i "input.mp4" -map 0 -c copy "real-output.mkv"
```

比较两者。写下“改名”和“重封装”分别改变了什么。

### 练习 3：比较容器级和流级信息

使用 JSON 输出找出：

- `format.format_name`。
- `streams[0].codec_name`。
- `streams[0].time_base`。
- `streams[0].tags.language`（如果存在）。

说明这些字段分别描述整个文件还是某条流。

### 练习 4：重封装并验证编码没有改变

把 MP4 重封装为 MKV，比较输入输出的 `codec_name`、宽高、采样率和流数量。

**预期结论**：容器名称可以改变，编码名称通常不变；如果编码也变了，那就是转码而不是简单 remux。

### 练习 5：找一个重封装失败的组合

尝试把一个含 H.264 的文件复制到 WebM，记录完整错误。回答：失败发生在“文件打不开”“编码器不存在”还是“目标容器不接受这组编码”哪一层？

### 练习 6：修改 C++ 查看器

修改 `media_inspector.cpp`，增加以下输出：

- 只打印视频流的编号。
- 只打印音频流的语言标签。
- 打印每条流的 `codec_tag`。
- 当时长未知时打印一条自定义提示。

### 练习 7：修改 C++ 重封装器

在 `media_remux.cpp` 中增加一个命令行选项，让程序只复制视频流，或者只复制音频流。完成后用 `ffprobe` 验证输出是否真的只剩目标流。

### 练习 8：时间基手算

从 `ffprobe` 或 C++ 输出中找出一条流的 `time_base` 和某个包的 `pts`，手算它对应的秒数，再和 `pts_time` 比较。

### 练习 9：资源所有权判断

回答下面三个问题：

1. `format_context->streams[index]` 是否需要 `delete`？
2. `av_packet_alloc()` 返回的 `AVPacket*` 如何释放？
3. 为什么输入关闭要调用 `avformat_close_input` 而不是 `free`？

**参考结论**：流由格式上下文拥有；包用 `av_packet_free`；格式上下文需要 FFmpeg 提供的关闭函数来释放内部资源。

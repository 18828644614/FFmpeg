# 时间戳与时间基

> 本章面向第一次接触 FFmpeg 时间概念的读者。你不需要先会写播放器，也不需要先记住所有英文缩写。先理解“一个整数怎样表示时间”，再理解这个整数在解封装、解码、编码和播放中怎样流动。

## 学完本章要达到的程度

完成本章后，你应该能够：

- 解释“时间戳不是秒”，并用时间基把它换算成秒。
- 区分 PTS、DTS、duration、start_time 和帧率。
- 解释为什么每条流可以有自己的 `time_base`。
- 读懂 `ffprobe` 的 `pts`、`dts`、`duration`、`*_time` 字段。
- 使用 `av_q2d`、`av_rescale_q`、`av_rescale_q_rnd` 和 `av_packet_rescale_ts` 做正确换算。
- 理解视频 B 帧、音频采样和音视频同步为什么会影响 PTS/DTS。
- 在 Windows + C++ + FFmpeg 下编译并运行时间换算、包时间戳查看和重封装示例。
- 遇到时间跳动、音画不同步、时长异常和输出无法播放时，知道先检查哪一层。

本章重点是“时间如何表达和换算”。完整的解码队列、主时钟和丢帧策略见 [[05-解封装与解码/音视频同步基础]] 与 [[08-播放器开发/音视频同步实现]]；编码器如何产生输出时间戳见 [[06-编码与封装/时间戳写出]]。

## 二、前置知识

### 2.1 必须会的最少内容

你只需要会下面这些，不要求先学完所有 C++：

- 在 PowerShell 中切换目录、运行程序、查看文件。
- 知道 C++ 源文件经过编译会得到 `.exe`。
- 看懂变量、函数、`if`、循环、指针和返回值。
- 知道整数除法会丢掉小数，例如 `1 / 2` 在两个整数中结果是 `0`。
- 知道 `.h` 是头文件，`.lib` 参与链接，`.dll` 在运行时被加载。
- 了解容器、流、数据包和帧的基本区别。可先阅读 [[03-FFmpeg基础/媒体文件与容器]]。

### 2.2 本章先建立的三个直觉

**直觉一：时间戳是带单位的整数。**

只看到 `pts=90000` 没有意义。必须同时看到时间基。例如：

```text
pts = 90000, time_base = 1/90000
时间 = 90000 × (1/90000) 秒 = 1 秒
```

**直觉二：不同流可以用不同的尺子。**

视频可能使用 `1/90000` 秒一个 tick，音频可能使用 `1/48000` 秒一个 tick。它们都可以准确表示时间，只是刻度不同。

**直觉三：顺序有两个。**

数据包到达解码器有一个顺序，解码后的画面和声音呈现又有一个时间顺序。B 帧会让这两个顺序不一样，这就是 PTS 和 DTS 同时存在的原因之一。

## 三、时间基：给整数时间戳配一把尺子

### 3.1 `AVRational` 是什么

FFmpeg 用 `AVRational` 表示分数：

```cpp
AVRational time_base = {1, 90000};
```

它表示：**一个时间戳单位等于 `1/90000` 秒**。如果时间戳是 `45000`：

```text
45000 × 1/90000 = 0.5 秒
```

通用公式是：

```text
秒数 = 时间戳 × time_base.num / time_base.den
```

在 C++ 中不要假设分母永远非零。遇到 `den == 0` 时，先把它当作无效分数处理。

### 3.2 为什么不用直接保存 double

如果所有时间都保存成 `double` 秒，长时间播放、频繁换算和多次取整可能产生累计误差。FFmpeg 更常用整数 tick 保存时间，需要显示时才换算成秒。

例如，`1/90000` 的时间基可以精确表示很多视频时间；`double` 只在打印或与外部 API 交互时使用。

### 3.3 常见时间单位

| 名称 | 写法 | 含义 |
| --- | --- | --- |
| 秒 | `s` | 人类最常用的播放时间单位 |
| 毫秒 | `ms` | `1/1000` 秒，常用于界面和日志 |
| 微秒 | `us` | `1/1000000` 秒，FFmpeg 全局时间基常用 |
| tick | 无固定写法 | 某个时间基下的一个整数单位 |

“tick”不是固定的时间长度。`1/1000` 时间基中的一个 tick 是 1 ms；`1/90000` 时间基中的一个 tick 约为 11.11 us。

### 3.4 三个手算例子

```text
time_base = 1/1000, pts = 2500
时间 = 2500 × 1/1000 = 2.5 秒

time_base = 1/48000, pts = 96000
时间 = 96000 × 1/48000 = 2 秒

time_base = 1001/30000, pts = 30
时间 = 30 × 1001/30000 = 1.001 秒
```

最后一个例子说明时间基不一定是 `1/整数`。`1001/30000` 常用于表示接近 29.97 fps 的时间间隔。

### 3.5 时间基和帧率不是同一个东西

- **帧率**表示每秒多少帧，例如 `30 fps`。
- **时间基**表示时间戳整数的一格代表多少秒，例如 `1/90000`。

一个 30 fps 的视频，如果时间基是 `1/90000`，相邻帧的时间戳通常相差 `3000`；如果时间基是 `1/1000`，相邻帧可能相差 `33` 或 `34`，需要通过取整近似表示 33.333 ms。因此不能拿 `avg_frame_rate` 直接当 `time_base`。

## 四、PTS、DTS、duration 和 start_time

### 4.1 PTS：应该什么时候呈现

**PTS（Presentation Timestamp）** 是呈现时间戳：

- 视频：这一帧应该在时间线上什么时候显示。
- 音频：这一帧中的第一批采样应该在什么时候播放。

PTS 的整数单位由对应流的时间基决定。`pts=0` 通常表示流的时间起点，但不保证整个文件一定从 0 开始。

### 4.2 DTS：什么时候交给解码器

**DTS（Decoding Timestamp）** 是解码时间戳，表示解码器处理这份压缩数据的大致顺序。

没有帧重排序时，PTS 和 DTS 可能相同。使用 B 帧的视频通常需要先解码参考帧，再输出显示顺序中的帧，因此可能出现：

```text
数据包到达/解码顺序（DTS）：I0 -> P2 -> B1
画面显示顺序（PTS）：      I0 -> B1 -> P2
```

不要用 `DTS` 直接决定画面显示时间，也不要要求所有包的 PTS 必须递增到和 DTS 一样。

### 4.3 duration：这段数据覆盖多长时间

`duration` 表示包或帧覆盖的时间长度，单位仍然是时间基 tick。

例如音频时间基为 `1/48000`，一个包包含 1024 个采样：

```text
duration = 1024 ticks
真实时长 = 1024 / 48000 秒 ≈ 21.333 ms
```

某些容器或实时输入可能没有可靠的 duration，字段会是 `AV_NOPTS_VALUE` 或 0。代码要先判断，不能把缺失值当成真实的 0 秒。

### 4.4 start_time：文件或流的起点偏移

`start_time` 描述输入的时间起点。在 MPEG-TS、直播流或经过剪切的文件中，第一包的 PTS 可能不是 0，甚至可能是负数。

“把所有负数时间戳强行改成 0”可能破坏音视频相对关系。是否需要平移，要根据目标容器、播放器和业务需求决定。

### 4.5 `AV_NOPTS_VALUE` 不是普通时间

FFmpeg 用 `AV_NOPTS_VALUE` 表示“没有可用时间戳”。判断方式：

```cpp
if (timestamp == AV_NOPTS_VALUE) {
    // 不能换算，也不能直接打印成秒。
}
```

不要把它传给普通乘法，不要把它显示成一个巨大负数，也不要用它判断“时间在文件最前面”。

## 五、FFmpeg 中常见的时间基位置

### 5.1 `AVStream::time_base`

解封装后，包的 `pts`、`dts` 和 `duration` 通常使用对应 `AVStream` 的 `time_base`。读取包时要用：

```cpp
AVRational tb = format->streams[packet->stream_index]->time_base;
```

这是最常用的“包时间基”。

### 5.2 `AVCodecContext::time_base`

编码器或解码器上下文也有 `time_base`。编码时，它通常是程序给编码器的输出时间刻度；解码时，具体含义要结合编解码器和 API 文档判断。

把 `AVCodecContext::time_base` 和 `AVStream::time_base` 直接当成相同是常见错误。编码器输出包后，写入容器前通常需要从 codec 时间基换算到 stream 时间基。

### 5.3 `AV_TIME_BASE`

FFmpeg 定义了：

```cpp
AV_TIME_BASE == 1000000
```

它表示一个微秒时间基 `1/1000000`。格式上下文中的某些全局字段，例如 `AVFormatContext::duration`，通常以微秒为单位；格式文档和具体字段说明优先于死记规则。

转换示例：

```cpp
const AVRational microseconds = {1, AV_TIME_BASE};
double seconds = av_q2d(microseconds) * format->duration;
```

### 5.4 `AVFrame::best_effort_timestamp`

解码器可能因为重排序或输入不完整，无法直接给出理想的帧时间戳。`best_effort_timestamp` 是 FFmpeg 根据已有信息估计出的可用时间戳，通常按流时间基解释。

初学阶段可以遵循这条规则：

```text
包时间：看 AVPacket + AVStream::time_base
解码帧时间：看 AVFrame 的时间戳 + 对应流的 time_base
写出包：先确认源时间基，再换到输出 AVStream::time_base
```

## 六、FFmpeg 的换算 API

### 6.1 `av_q2d`：分数转小数

```cpp
double seconds_per_tick = av_q2d(stream->time_base);
double seconds = timestamp * seconds_per_tick;
```

适合日志和界面显示。它返回 `double`，不要用它作为长时间轴的唯一内部存储。

### 6.2 `av_rescale_q`：在两个时间基之间换算

```cpp
int64_t target = av_rescale_q(
    source,
    source_time_base,
    target_time_base);
```

数学含义是：

```text
source × source_time_base / target_time_base
```

例如，把 1500 ms 换成 `1/90000`：

```cpp
AVRational milliseconds = {1, 1000};
AVRational video = {1, 90000};
int64_t pts = av_rescale_q(1500, milliseconds, video); // 135000
```

优先使用这个 API，不要自己写容易溢出的 `source * num * den / ...`。

### 6.3 `av_rescale_q_rnd`：明确取整方式

换算结果不一定是整数。例如把 1 ms 换成 `1/30` 秒的时间基时，必须取整。可以显式指定：

```cpp
int64_t value = av_rescale_q_rnd(
    source,
    source_tb,
    target_tb,
    AV_ROUND_NEAR_INF | AV_ROUND_PASS_MINMAX);
```

常见取整选择：

- `AV_ROUND_NEAR_INF`：取最接近的整数。
- `AV_ROUND_DOWN`：向负无穷取整。
- `AV_ROUND_UP`：向正无穷取整。
- `AV_ROUND_PASS_MINMAX`：让 `AV_NOPTS_VALUE` 这类特殊值保持不变。

负时间戳存在时，向下和向零不是同一件事。除非你明确知道业务要求，否则让 FFmpeg 的专用 API 处理。

### 6.4 `av_packet_rescale_ts`：一次处理包的三个时间字段

重封装或编码输出时，通常需要同时换算 `pts`、`dts` 和 `duration`：

```cpp
av_packet_rescale_ts(packet, input_tb, output_tb);
```

这个函数会处理 `AV_NOPTS_VALUE`，比手动给三个字段分别赋值更不容易漏项。

### 6.5 换算方向必须写清楚

```cpp
// 输入包原来以 input_tb 表示，输出流使用 output_tb。
av_packet_rescale_ts(packet, input_tb, output_tb);
```

如果把源和目标反过来，程序通常仍能运行，但输出时长、帧率和同步会完全错误。建议在代码旁边写一句“这个字段当前属于哪把尺子”。

## 七、用 `ffprobe` 观察真实时间戳

### 7.1 先生成一个可控的测试文件

在 PowerShell 中执行。下面命令使用测试图和正弦波，不需要准备摄像头或麦克风：

```powershell
ffmpeg -hide_banner -y `
  -f lavfi -i "testsrc=size=640x360:rate=30" `
  -f lavfi -i "sine=frequency=440:sample_rate=48000" `
  -t 5 `
  -c:v libx264 -pix_fmt yuv420p `
  -c:a aac -ar 48000 -ac 1 `
  .\timestamp-sample.mp4
```

如果当前构建没有 `libx264`，可以把视频编码器改成该构建可用的编码器；本实验重点是时间字段。

### 7.2 查看流级时间信息

```powershell
ffprobe -hide_banner .\timestamp-sample.mp4

ffprobe -v error `
  -show_entries "stream=index,codec_type,codec_name,time_base,start_time,duration,avg_frame_rate" `
  -of default=noprint_wrappers=1 `
  .\timestamp-sample.mp4
```

重点观察：

- `time_base`：例如 `1/90000` 或 `1/48000`。
- `start_time`、`duration`：它们是按各自字段约定输出的秒值或时间信息。
- `avg_frame_rate`：这是帧率，不是时间基。

### 7.3 查看包级 PTS、DTS 和 duration

```powershell
ffprobe -v error `
  -select_streams v:0 `
  -show_entries packet=stream_index,pts,pts_time,dts,dts_time,duration,duration_time,flags `
  -of csv=p=0 `
  .\timestamp-sample.mp4 | Select-Object -First 12
```

再看音频：

```powershell
ffprobe -v error `
  -select_streams a:0 `
  -show_entries packet=stream_index,pts,pts_time,dts,dts_time,duration,duration_time `
  -of csv=p=0 `
  .\timestamp-sample.mp4 | Select-Object -First 12
```

`pts_time`、`dts_time` 和 `duration_time` 是 FFprobe 帮你换算后的秒值。练习时先遮住这些列，用整数和 `time_base` 手算，再对照结果。

### 7.4 查看解码帧时间

```powershell
ffprobe -v error `
  -select_streams v:0 `
  -show_frames `
  -show_entries frame=best_effort_timestamp,best_effort_timestamp_time,pkt_dts,pkt_dts_time,pkt_duration,pkt_duration_time,pict_type `
  -of csv=p=0 `
  .\timestamp-sample.mp4 | Select-Object -First 12
```

包和帧的字段不一定一一对应。一个包可能需要多个包才能解码出帧，也可能一个包中包含一段音频帧。

## 八、Windows + C++ + FFmpeg 示例

下面三个程序分别练习：纯时间基换算、读取真实包时间戳、重封装时换算时间戳。示例假设你已有与 MSVC x64 匹配的 FFmpeg 开发包：

```text
C:\ffmpeg\include\libavutil\...
C:\ffmpeg\include\libavformat\...
C:\ffmpeg\lib\*.lib
C:\ffmpeg\bin\*.dll
```

请从 **Visual Studio Developer PowerShell** 执行命令，以确保 `cl.exe` 可用。

### 8.1 示例一：把 1500 毫秒换成视频时间基

保存为 `timestamp_demo.cpp`：

```cpp
#include <cstdint>
#include <iostream>

extern "C" {
#include <libavutil/mathematics.h>
#include <libavutil/rational.h>
}

int main() {
    const AVRational milliseconds = {1, 1000};
    const AVRational video_time_base = {1, 90000};
    const std::int64_t timestamp_in_ms = 1500;

    const std::int64_t video_ticks = av_rescale_q(
        timestamp_in_ms, milliseconds, video_time_base);

    const std::int64_t round_trip_ms = av_rescale_q(
        video_ticks, video_time_base, milliseconds);

    std::cout << "1500 ms = " << video_ticks
              << " ticks in a 1/90000 time base\n";
    std::cout << "back to milliseconds = " << round_trip_ms << "\n";
    return 0;
}
```

编译、运行：

```powershell
cl /std:c++17 /EHsc timestamp_demo.cpp `
  /I C:\ffmpeg\include `
  /link /LIBPATH:C:\ffmpeg\lib avutil.lib

$env:Path = "C:\ffmpeg\bin;$env:Path"
.\timestamp_demo.exe
```

预期输出：

```text
1500 ms = 135000 ticks in a 1/90000 time base
back to milliseconds = 1500
```

这里没有读媒体文件，目的是先把“源时间基 -> 目标时间基”的方向练熟。

### 8.2 示例二：打印前 20 个包的 PTS、DTS 和 duration

保存为 `packet_timestamps.cpp`：

```cpp
#include <cstdint>
#include <iomanip>
#include <iostream>
#include <string>

extern "C" {
#include <libavcodec/packet.h>
#include <libavformat/avformat.h>
#include <libavutil/error.h>
#include <libavutil/rational.h>
}

static std::string ffmpeg_error(int code) {
    char buffer[AV_ERROR_MAX_STRING_SIZE] = {};
    av_strerror(code, buffer, sizeof(buffer));
    return buffer;
}

static void print_timestamp(
    const char* name, std::int64_t value, AVRational time_base) {
    std::cout << name << "=" << value;
    if (value != AV_NOPTS_VALUE && time_base.den != 0) {
        std::cout << " (" << std::fixed << std::setprecision(6)
                  << value * av_q2d(time_base) << " s)";
    } else if (value == AV_NOPTS_VALUE) {
        std::cout << " (NOPTS)";
    }
}

int main(int argc, char* argv[]) {
    if (argc != 2) {
        std::cerr << "Usage: packet_timestamps.exe <input-media>\n";
        return 2;
    }

    AVFormatContext* format = nullptr;
    int result = avformat_open_input(&format, argv[1], nullptr, nullptr);
    if (result < 0) {
        std::cerr << "Could not open input: " << ffmpeg_error(result) << "\n";
        return 1;
    }

    result = avformat_find_stream_info(format, nullptr);
    if (result < 0) {
        std::cerr << "Could not read stream information: "
                  << ffmpeg_error(result) << "\n";
        avformat_close_input(&format);
        return 1;
    }

    std::cout << "Streams: " << format->nb_streams << "\n";
    for (unsigned int i = 0; i < format->nb_streams; ++i) {
        const AVStream* stream = format->streams[i];
        std::cout << "stream " << i << " time_base="
                  << stream->time_base.num << "/"
                  << stream->time_base.den << "\n";
    }

    AVPacket* packet = av_packet_alloc();
    if (packet == nullptr) {
        std::cerr << "Could not allocate packet\n";
        avformat_close_input(&format);
        return 1;
    }

    int count = 0;
    while (count < 20 && (result = av_read_frame(format, packet)) >= 0) {
        const AVStream* stream = format->streams[packet->stream_index];
        std::cout << "packet " << count
                  << " stream=" << packet->stream_index << " ";
        print_timestamp("pts", packet->pts, stream->time_base);
        std::cout << " ";
        print_timestamp("dts", packet->dts, stream->time_base);
        std::cout << " ";
        print_timestamp("duration", packet->duration, stream->time_base);
        std::cout << " size=" << packet->size << "\n";

        av_packet_unref(packet);
        ++count;
    }

    if (result < 0 && result != AVERROR_EOF) {
        std::cerr << "Could not read packet: " << ffmpeg_error(result) << "\n";
    }

    av_packet_free(&packet);
    avformat_close_input(&format);
    return result < 0 && result != AVERROR_EOF ? 1 : 0;
}
```

### 8.3 示例三：重封装时换算包时间戳

保存为 `remux_with_rescale.cpp`。这个程序不解码、不重新编码，只把媒体包复制到由输出扩展名选择的容器中；时间戳是本示例的重点。

```cpp
#include <iostream>
#include <string>
#include <vector>

extern "C" {
#include <libavcodec/avcodec.h>
#include <libavcodec/codec_par.h>
#include <libavcodec/packet.h>
#include <libavformat/avformat.h>
#include <libavutil/error.h>
}

static std::string ffmpeg_error(int code) {
    char buffer[AV_ERROR_MAX_STRING_SIZE] = {};
    av_strerror(code, buffer, sizeof(buffer));
    return buffer;
}

int main(int argc, char* argv[]) {
    if (argc != 3) {
        std::cerr << "Usage: remux_with_rescale.exe <input> <output>\n";
        return 2;
    }

    AVFormatContext* input = nullptr;
    AVFormatContext* output = nullptr;
    AVPacket* packet = nullptr;
    int result = avformat_open_input(&input, argv[1], nullptr, nullptr);
    if (result < 0) {
        std::cerr << "Could not open input: " << ffmpeg_error(result) << "\n";
        return 1;
    }

    result = avformat_find_stream_info(input, nullptr);
    if (result < 0) {
        std::cerr << "Could not read stream information: "
                  << ffmpeg_error(result) << "\n";
        avformat_close_input(&input);
        return 1;
    }

    result = avformat_alloc_output_context2(
        &output, nullptr, nullptr, argv[2]);
    if (result < 0 || output == nullptr) {
        std::cerr << "Could not create output context: "
                  << ffmpeg_error(result) << "\n";
        avformat_close_input(&input);
        return 1;
    }

    std::vector<int> stream_map(input->nb_streams, -1);
    for (unsigned int i = 0; i < input->nb_streams; ++i) {
        const AVStream* input_stream = input->streams[i];
        const AVMediaType type = input_stream->codecpar->codec_type;
        if (type != AVMEDIA_TYPE_VIDEO && type != AVMEDIA_TYPE_AUDIO
            && type != AVMEDIA_TYPE_SUBTITLE) {
            continue;
        }

        AVStream* output_stream = avformat_new_stream(output, nullptr);
        if (output_stream == nullptr) {
            std::cerr << "Could not create output stream\n";
            avformat_close_input(&input);
            avformat_free_context(output);
            return 1;
        }

        result = avcodec_parameters_copy(
            output_stream->codecpar, input_stream->codecpar);
        if (result < 0) {
            std::cerr << "Could not copy codec parameters: "
                      << ffmpeg_error(result) << "\n";
            avformat_close_input(&input);
            avformat_free_context(output);
            return 1;
        }

        output_stream->codecpar->codec_tag = 0;
        output_stream->time_base = input_stream->time_base;
        stream_map[i] = static_cast<int>(output_stream->index);
    }

    if ((output->oformat->flags & AVFMT_NOFILE) == 0) {
        result = avio_open(&output->pb, argv[2], AVIO_FLAG_WRITE);
        if (result < 0) {
            std::cerr << "Could not open output: " << ffmpeg_error(result)
                      << "\n";
            avformat_close_input(&input);
            avformat_free_context(output);
            return 1;
        }
    }

    result = avformat_write_header(output, nullptr);
    if (result < 0) {
        std::cerr << "Could not write header: " << ffmpeg_error(result) << "\n";
        if (output->pb != nullptr
            && (output->oformat->flags & AVFMT_NOFILE) == 0) {
            avio_closep(&output->pb);
        }
        avformat_close_input(&input);
        avformat_free_context(output);
        return 1;
    }

    packet = av_packet_alloc();
    if (packet == nullptr) {
        std::cerr << "Could not allocate packet\n";
        av_write_trailer(output);
        if (output->pb != nullptr
            && (output->oformat->flags & AVFMT_NOFILE) == 0) {
            avio_closep(&output->pb);
        }
        avformat_close_input(&input);
        avformat_free_context(output);
        return 1;
    }

    while ((result = av_read_frame(input, packet)) >= 0) {
        const int output_index = stream_map[packet->stream_index];
        if (output_index < 0) {
            av_packet_unref(packet);
            continue;
        }

        const AVStream* input_stream = input->streams[packet->stream_index];
        AVStream* output_stream = output->streams[output_index];
        packet->stream_index = output_index;

        // The muxer may adjust output_stream->time_base while writing the header.
        av_packet_rescale_ts(
            packet, input_stream->time_base, output_stream->time_base);
        packet->pos = -1;

        result = av_interleaved_write_frame(output, packet);
        av_packet_unref(packet);
        if (result < 0) {
            std::cerr << "Could not write packet: " << ffmpeg_error(result)
                      << "\n";
            break;
        }
    }

    if (result == AVERROR_EOF) {
        result = av_write_trailer(output);
        if (result < 0) {
            std::cerr << "Could not write trailer: " << ffmpeg_error(result)
                      << "\n";
        }
    }

    av_packet_free(&packet);
    if (output->pb != nullptr && (output->oformat->flags & AVFMT_NOFILE) == 0) {
        avio_closep(&output->pb);
    }
    avformat_close_input(&input);
    avformat_free_context(output);
    return result < 0 ? 1 : 0;
}
```

## 九、seek、负时间戳和音视频同步的基础

### 9.1 seek 的时间单位

`avformat_seek_file` 的 `timestamp` 单位取决于 `stream_index`：

- `stream_index >= 0`：使用该流的 `AVStream::time_base`。
- `stream_index == -1`：通常使用 `AV_TIME_BASE` 微秒时间基。

示例：跳到视频流 10 秒附近：

```cpp
const AVStream* video = format->streams[video_index];
const int64_t target = av_rescale_q(
    10, AVRational{1, 1}, video->time_base);

int ret = avformat_seek_file(
    format,
    video_index,
    INT64_MIN,
    target,
    INT64_MAX,
    0);
```

seek 后通常还要：

1. 调用 `avcodec_flush_buffers(codec_context)` 清空解码器旧数据。
2. 重新读取包并解码。
3. 丢弃目标时间之前的帧，直到达到目标位置。

容器通常只能快速跳到目标前面的关键帧，不能保证第一帧就是精确目标时间。

### 9.2 为什么播放器不能只看系统时间

播放器至少有三种时间：

- **媒体时间**：包和帧中的 PTS。
- **音频时钟**：声卡实际播放到哪里。
- **墙上时钟**：Windows 当前时间或高精度计时器。

常见做法是让音频时钟作为主时钟：

```text
视频帧 PTS - 当前音频时钟 > 0：画面还早，等待
视频帧 PTS - 当前音频时钟 < 0：画面落后，丢弃或立即显示
```

真实播放器还要处理缓冲、暂停、变速、音频设备延迟和时钟漂移。本章只要求你理解“比较前必须把时间换到同一时间基或同一秒单位”。

### 9.3 音频时间的特殊直觉

采样率为 48000 Hz 时：

```text
第 0 个采样 -> 0 秒
第 48000 个采样 -> 1 秒
第 96000 个采样 -> 2 秒
```

如果音频帧包含 1024 个采样，并且时间基为 `1/48000`，它的 duration 通常是 1024 tick。音频与视频同步时，不能把“音频帧编号”直接当成秒，也不能把“视频帧编号”直接和音频帧编号比较。

### 9.4 编码时生成时间戳的简单规则

以固定帧率视频为例，如果编码器时间基是 `1/30`，第 `n` 帧的 PTS 可以从 `n` 开始；如果时间基是 `1/90000`，同样的帧要使用 `n * 3000`。这说明 PTS 的整数值依赖时间基。

音频通常按已经处理的样本数生成 PTS：

```text
audio_pts = 已经送入编码器的样本数
time_base = 1 / sample_rate
```

实际编码还要考虑编码器延迟、可变帧大小、重采样和容器约束，详细流程见 [[06-编码与封装/时间戳写出]]。

## 十、常见错误和排查顺序

遇到时间问题时，按下面顺序排查：先确认字段含义，再确认时间基，再确认换算方向，最后才看播放器行为。

| 现象 | 常见原因 | 排查方法 |
| --- | --- | --- |
| `pts=90000` 被当成 90000 秒 | 忘记乘以 `time_base` | 同时打印 `stream->time_base`，用 `av_q2d` 换算 |
| 视频播放速度异常 | 把帧率当时间基，或时间基方向反了 | 分别打印 `avg_frame_rate` 和 `time_base` |
| 音频变速、变调 | 音频包时间戳没有从源时间基换到目标时间基 | 用 `av_packet_rescale_ts`，检查音频流的 time base |
| 输出时长为 0 或极大 | 直接复制整数时间戳 | 写包前按输入和输出时间基换算 |
| PTS/DTS 是巨大负数 | 直接打印了 `AV_NOPTS_VALUE` | 先判断 `value == AV_NOPTS_VALUE` |
| 包的 PTS 顺序不递增 | B 帧重排序、负时间戳或输入本身不连续 | 分开观察 PTS 和 DTS，不要强行排序 |
| seek 后画面跳回很早的位置 | 只能定位到关键帧 | seek 后解码并丢弃目标前的帧 |
| seek 后画面或声音继续使用旧内容 | 没有 flush 解码器 | 调用 `avcodec_flush_buffers` |
| 音画逐渐不同步 | 使用错误时钟、累计取整误差或丢包 | 把音频时钟、视频 PTS、墙上时钟分别记录 |
| `av_rescale_q` 结果少 1 tick | 取整方式与预期不同 | 使用 `av_rescale_q_rnd` 明确 rounding |
| 负时间戳被错误截断 | 把有符号时间当无符号，或手写整数除法 | 使用 FFmpeg rescale API，保留 `int64_t` |
| 输出文件打不开 | 没有写 trailer，或时间戳违反容器约束 | 检查 `av_write_trailer` 和写包错误 |
| C++ 编译找不到头文件 | `include` 路径错误 | 检查 `C:\ffmpeg\include\libavutil\rational.h` |
| 链接找不到 `avutil.lib` | `lib` 路径或架构不匹配 | 使用 x64 Developer PowerShell 和同架构库 |
| 启动时缺少 DLL | `bin` 不在 PATH | `$env:Path = "C:\ffmpeg\bin;$env:Path"` |
| `ffprobe` 和 C++ 输出版本不一致 | PATH 中加载了不同 FFmpeg 版本 | 使用 `where.exe ffprobe`、检查 exe 目录和 DLL 来源 |
